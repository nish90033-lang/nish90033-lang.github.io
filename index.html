SmartRAG: Retrieval Augmented Generation System

IEEE TENCON 2026
Python · FastAPI · LangChain · PostgreSQL · TF-IDF · BM25 · Groq Llama 3.3 70B
  • Designed and deployed a production RAG pipeline for multi-document collections of 500+ pages behind a FastAPI backend on Render, with 2.47s average end-to-end query latency on a 10-document, 864-chunk evaluation corpus.
  • Retrieval accuracy counts a query as correct when the right passage appears in the top 9 retrieved chunks. On a 60-query test set (52 answerable, 8 out-of-scope), a 70/30 weighted hybrid of HashingVectorizer TF-IDF and BM25 reached 92% (48 of 52), versus 69% (36 of 52) for TF-IDF alone. All 8 out-of-scope queries returned unanswerable.
  • Cut peak memory from roughly 700MB (OOM crash) to 60 to 80MB by replacing TfidfVectorizer with HashingVectorizer, which keeps memory fixed as the corpus grows.
  • Built a three-layer anti-poisoning pipeline (regex sanitization, binary hard-cap trust scoring, retrieval-time blocking) against prompt injection through ingested documents. Tested against 20 adversarial prompt-injection attempts across 4 attack categories, it stopped all 20. This result covers my test set only, not every possible injection.
